# Wave24 explicit evidence catalog protocol

This is transport and publication preparation, with no mathematical verification, solver call, ledger mutation, Git index change, or publication operation. The new source adapts the frozen wave23 catalog. Existing research files, failed versions, and raw originals remain unchanged.

The frozen cohort is 248 claims: 244 VERIFIED/CLEAR, 2 CANDIDATE/CLEAR and 2 REFUTED/CLEAR. The ordered contiguous registration chain is twentyfourth_base, twentyfourth_count, twentyfourth_gram, twentyfourth_final. Its 19 additions contain 18 verified claims and one refuted exact-equality proposal. The valid loose Frechet inequalities are not refuted. The target remains UNKNOWN.

The source contains literal DIRECTORY and FILE whitelists. Additional publication wrapper files are accepted only as explicit command arguments and are reported in the resulting catalog. Research includes the first seven-profile proof, all 215 remaining formulas and complete native/proof campaign, count-master and interval models and witnesses, exact Frechet counterexample, literal eight-profile formula and exclusion, mathematical six-orbit cuts, separate 3x3 Gram-block screen, affine GF(2) relaxation, independent audits, preserved failed versions and registration chains. Wave23 publication completion and replay-guide corrections are retained.

Future orbit-cut native pilot, its preflight, its object checker/calibration and later full-catalogue work are excluded, even if subsequently completed. Historical unregistered leftovers are not included merely because they are untracked. The protected user prompt, private process snapshot, tool submodule changes and secret file classes remain excluded. No scan reads the old private process arguments.

Every selected raw research artifact over 10 MiB must have exact public gzip recovery. For consistency, all new research proof/partial-trace originals are also LOCAL_ONLY with recovery, regardless of size. These include two small literal UNSAT proofs and the incomplete SAT count-master trace, which is explicitly not an UNSAT certificate. Tiny proof corruption controls remain public. The 12.6 MB local-decoder calibration artifact is separately packaged. Raw originals are preserved. Manifest normalization uses only explicitly listed manifests plus exactly the 215 formula package records in the complete run02 summary.

Recovery streams are checked for ordered offsets, each compressed/raw part hash and length, and whole raw hash/length against the retained original. Standalone compressed JSON artifacts already serving as raw evidence remain raw compressed artifacts, authenticated by their saved hashes. Deterministic gzip uses level 9, mtime 0, empty filename. Corrupted/truncated gzip controls are exercised in the supplementary packager.

The research payload ceiling is 10 MiB per public file. Only the exact catalog.json, stage_inventory.json, and reference_checks.json.gz paths inside twentyfourth_preparation or twentyfourth_artifact_packaging may use a 32 MiB ceiling. No blanket directory exemption exists.

Reference serialization is preregistered as WAVE24_REFERENCE_MANIFEST_V1. The named reference_checks.json.gz is a deterministic gzip UTF-8 JSON manifest with ordered `parts`, `record_count`, `unique_referenced_files`, and `gzip_recoveries`. Each `reference_checks.partNNNN.json.gz` decodes to WAVE24_REFERENCE_CHUNK_V1 with `index` and exact ordered `records`, at most 25,000 records and at most 10 MiB compressed. Each manifest entry pins repository-relative path, SHA256, compressed bytes, index, cumulative record_offset and record count. This replaces the wave23 single large reference-record list without discarding references. The catalog buffers only one part at a time. A named manifest, not a file-size exception, provides reconstruction.

All real dependency references must resolve to selected files, byte-authenticated tracked files, explicitly prior recoverable inputs, exact local tool binaries, or the frozen source archive. A deliberate malformed control reference may be excluded only by an exact origin/path/hash tuple with an explicit reason; no general mismatch suppression is allowed. Current ledger references in registrar validation are mapped to immutable after snapshots. Package checks, exact Git blob-byte checks and unchanged ledger/index checks are mandatory.

Commands use the existing locked uv environment. Preparation and finalization use distinct fresh output directories and preserve source/failure receipts on error. No automatic retry or source replacement after a failed execution. Root controls checkpoint, report, staging, commits and public pointers. Successful catalog status means READY_FOR_PUBLICATION, never already public.
