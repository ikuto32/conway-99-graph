# Batch05 frozen checkpoint identity review, version 1

This independent checker does not import the native driver or producer. It reads
the exact saved 2026-10-01 checkpoint, selection, consolidation, mathematical
encoding gate and object calibration gate; hashes the selected eight-file case
records; and independently parses every line of all 64 raw CNFs. Accepted clause
syntax requires the recorded header, one zero-terminated clause per line, no
interior zero, integer literals in range, and the exact recorded clause count.
It authenticates the source closure of the historical independent object checker
and disallows direct imports of producer/native modules in that closure.

The scientific scope is identity and DIMACS shape of prepared formulas on one
literal fixed support. Success requires the exact ordered 64-case population,
10,532,344 raw clauses, frozen digest/size agreement for all selected artifacts,
both approved gate identities, and all positive/corrupted parser controls.
No numerical tolerance is used. Historical gate input paths are inventoried for
availability; the default invocation does not rehash their complete transitive
20,040-path closure. The output explicitly lists skipped digests. Optional
`--scan-full-gate-closure` needs its own evidence-based supervised allocation.

This authenticates historical mathematical review records but does not repeat
their complete encoding derivation or any old proof replay. It does not calibrate
the new native driver and cannot authorize changed execution. It produces no
new exclusion and no target-resolution claim. The shared SHA-256, Python runtime,
filesystem and `tqdm` library remain trusted components. Saved checkpoint tallies
are bookkeeping and retain their restricted literal scopes.

The actual first run used the existing pinned `uv.lock` on Windows with
`UV_PROJECT_ENVIRONMENT=build/research-venv`, through
`acceleration/run_compute_command.py` with a 300-second invocation budget and
five-second shutdown reserve. The exact argv, Job containment, exit/cleanup
observations and allocation rationale are in
`results/20261002_independent_review/batch05_checkpoint_supervision01/`.
The checker report is in
`results/20261002_independent_review/batch05_checkpoint_identity01/`.
The root researcher must review this report and its limits before relying on it.

All outputs are created exclusively in a fresh directory. A failure report
preserves checked digests. Raw historical artifacts are never rewritten.
