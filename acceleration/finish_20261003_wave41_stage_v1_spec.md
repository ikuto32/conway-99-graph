## Controls and acceptance

Calibration inspects no actual apply report, manifest, selected evidence or
registry output and changes no index. It checks six synthetic positive records:
an exact466-path NUL, exact apply descriptor, valid Python source, benign marker
bytes, four synthetic marker patterns, and a cross-block marker boundary.
Eighteen negatives require precise stages: four NUL omissions/duplicates/
termination/member mutations, twelve apply-field mutations including float/bool
counts and wrong index, a missing apply field, and invalid Python source.
Wrong-stage exceptions or an accepted corruption veto the invocation.

Finish requires a fresh unchanged-source/spec successful calibration and repeats
those controls. Four current notice files must equal the original prepared
bytes; saved before bytes must equal their immutable Git00ff blobs and be exact
suffixes. The new milestone must equal `milestone.prepared.md` byte for byte,
including the known cosmetic unescaped `|C|` table text. No editorial repair is
made here. ROOT will preserve the original publication before any later repair.

Every selected Python source is parsed without executing it. Credential-pattern
checks examine only selected nongzip bytes in bounded blocks with a 256-byte
overlap; gzip payload identity remains the already checked selected artifact
identity. A veto records only the path/stage, never a possible credential value.
These four patterns are a finite marker check, not a universal secret detector.

All selected paths have their raw Git blob identities checked after staging the
explicit appendix NUL. No outside entry may change or appear; Gitlinks and the
ledger stay identical. Any failure preserves `failure.json`, whether an index
operation began and the observed index hash. No automatic retry, commit, push,
availability promotion, ledger edit, scientific computation or mathematical
replay is provided. ROOT must separately review and authorize any execution.
