## Independent mathematical path

The byte parser separately decodes the literal n header and n binary rows,
accepting the producer's LF/CRLF row endings without replacing the hash-bound
original. Dimensions, zero diagonal, symmetry, degree and row domains are
checked independently. Neighbors are represented as integer bit masks. Each
candidate removes both old edges and inserts the two orientation-specific
new edges in a fresh whole adjacency object. No incremental common-neighbor
or cost-update formula is used. All unordered pair costs are recomputed from
exact row-set intersections, including changed final edge categories.

The independent full product path computes every n*n integer entry by set
intersection. A second direct integer matrix dot-product path calibrates this
on each small base/valid candidate and the synthetic99 base/two probes. Its
diagonal is the true degree, not the zero-diagonal convention of old triple
engines. E_lambda/E_mu/F3/residue populations and scalar819820 are exact.
An inverse whole adjacency operation in own calibration is an oracle control,
not evidence that the native API's reverse/rollback branch ran.

Labels are derived from literal canonical old edges, i<j then orientation0,1.
The role rejection order, exact19 fields, 4n-10 affected count, signed deltas,
eight-integer key and all metric fields are reconstructed. Shared endpoints
are explicit invalid attempts. Valid graph keys are checked on every record;
their injectivity is derived in the separate Native written static review.
All rankings exclude the base, retain every minimum-F3 and minimum-(F3,E) tie,
and select the first pair-minimum ID. Tied (F3,E) records may have different
E_lambda/E_mu, so stored minimum metrics are those of the first selected tie.

## Narrow native-directory checking mode

`native-prefix` requires an explicit raw input path/SHA, n, degree, historical
source-context40hex, native mode and expected completeness. It makes no native
call. The supplied input is hashed before/after, then an authentic completed
native directory is checked from proposal0 to its literal stop ID. A complete
population has m*(m-1) records; a cooperative prefix has its observed count,
not a prefilled timeout count or an absence claim.

Every closed part has a strict header, at most5000 consecutive19-field records,
strict footer and a matching generated checkpoint. Every checkpoint aggregate,
key population, invalid-stage count, tie and selected ID is rebuilt from raw
records. Complete target99/14 would have479556 records/96parts/96checkpoints;
this source-only interface does not authorize that expensive replay. The
directory's canonical input, universe, complete manifest, selected record/raw
matrix and every raw-F3-zero export are checked. The selected full n*n product
is independently compared with direct scalar dot products. Exact file
population is required; no unexpected file, directory or symlink is accepted.

An unfinished manifest may preserve `part_<index>.jsonl.partial`; those bytes
are hashed and listed as **not approved**, never counted or parsed into the
closed record population. A complete manifest cannot have a partial tail.
There is no resume implementation or restart claim. A failed run without a
native manifest remains failed/not covered rather than being invented as a
checked prefix.
