# Exact interval count-master extension inventory

This new producer inventory is separate from the frozen count-master build. It performs no native, SAT, LP or MIP call, emits no research CNF, and gives no independent approval. The selected base is the separately justified at-least-seven formula. The interval inequalities are necessary for any actual full-Gram factor compatible with a selected count signature; interval feasibility does not construct such a factor.

Inputs are the exact frozen baseline and at-least-seven CNFs/model, the authenticated 6,061 by 135 interval table and its independent gate, and the literal fixed support and prescribed Gram. All 540 nonmatched-coordinate/fibre cells are selected in lexicographic coordinate-pair then fibre-pair order. Each has exactly five incident groups. For each group's selected count class, lower and upper coefficients are read literally from the table; the inventory must first establish that their complete range is 0..2. No scalar Frechet substitute is permitted.

For every lower/upper coefficient, threshold positions one and two encode coefficient >= threshold. A channel is the OR of precisely those existing group selectors whose class coefficient reaches that threshold. Sharing is preregistered: identical (group ID, group-selector-index subset) requests share one channel. Empty subsets are false; full subsets are true using the baseline exactly-one premise; singleton subsets reuse their existing positive literal. Other subsets receive one new variable and full OR clauses (-selector OR channel) for every member and (-channel OR all members). Subsets are represented as arbitrary-precision little-endian membership bit masks rather than large repeated integer tuples. No complement sharing or semantic subset equivalence is used. New channels are allocated by first request order, visiting each cell's groups in ascending order and then lower1,lower2,upper1,upper2.

After all channels are allocated, each cell gets an exact lower sum <= target and upper sum >= target, with all ten positions retained including repeated literals and constants. Prefix t(i,j) is t(i-1,j) OR (x_i AND t(i-1,j-1)); zero/one boundary constants are literal Booleans. Lower counters go through target+1 and end in a negative unit; upper counters go through target and end in a positive unit. Each gate emits every full maxterm for a false valuation of its sorted distinct nonconstant variables. Counts and ASCII bytes use LF lines with a single space between literals and terminating ' 0\n'; no giant clause list is retained. The full file reuses the exact augmented base body and changes its header. Counter records preserve every allocated state and exact clause/byte ranges. Repeated threshold inputs are deliberately not deduplicated.

Record both the selected shared construction and an unshared-channel comparison using the same constant/singleton rules. Exact selected totals include the changed DIMACS header. Save all masks, 540 cell/group mappings and counter configuration in deterministic compressed JSON, together with source/input hashes and control results. A future build requires a separate authorization/protocol and independent encoding/object gates.

Controls precede research inventory: exhaustive small OR relations (including constants/singletons), exact prefix truth controls with repeated and constant inputs, a known all-balanced count-CSP positive, and corrupted channel/threshold values. No positive control is represented as a full research factor. The command uses locked/offline uv and a fresh output directory. Cooperative inventory allocation: 60 seconds, 768 MiB planning ceiling; save a failure if exceeded, never silently change allocation. Expected memory is checked before loading the model/table, and actual peak working set is recorded if available through the process API. No existing source/artifact, ledger, index or Git mutation.

Command: `uv run --locked --offline --cache-dir .uv-cache-20260917 python -B acceleration/theory_20260930_count_interval_inventory.py --out acceleration/results/20260930_count_interval_inventory`
