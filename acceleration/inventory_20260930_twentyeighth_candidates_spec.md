# Wave 28 candidate inventory protocol

This is a read-only artifact inventory for the frozen 294-record checkpoint
87eed00b74925fc752375a1aaa4884eeb4221fef4b499ec7767a8bb03ba9875a and the
four contiguous wave-28 registration cohorts. The frozen ledger snapshot has
287 VERIFIED, 3 CANDIDATE, and 4 REFUTED records. The eight additions comprise
six scientific results and two engineering refutations. Existing audit verdicts
are premises for metadata selection; this program supplies no mathematical approval.

The source freezes the exact directory and file allowlists before execution.
It includes next32 and sizeclass16 formula builds, failed partial build contents,
native receipts, complete proof reviews, first12 fibre-union review versions,
the all792 common-kernel result, and failed launcher/control preparations.
Sibling specs are considered only for the explicitly named source stems.
Protected process.stdout.log files, PROMPT.md, current CLAIMS.yaml, tools/, and
secret-shaped paths are rejected before any read or hash. Next64,
run_four_builds replacement work, explicit checker v3, proof auditor v2, and
unregistered affine-GF3 work are excluded. No broad result-directory selection.

The program authenticates the frozen checkpoint/snapshot and four exact
before/after ledger byte transitions. It reads prior catalog metadata solely
to label earlier dependencies, without invoking Git or claiming fresh public
availability. Each selected file is hashed and sized. Selected JSON metadata
provides reference and package inventories; large model and initial-domain
payloads are hashed but not parsed. Out-of-allowlist references remain names
and declared hashes only; they do not expand the allowlist. Static imports
are identified without importing or executing repository code.

Before hashing the selected population, reject inventories exceeding 20,000
files or 4 GiB of selected bytes. Use a 120-second cooperative bound checked
between files, preserving an explicit PARTIAL result if reached. Report all
payloads over 10 MiB and whether existing metadata identifies a corresponding
gzip recovery stream. Do not decompress or certify recovery. Recorded hashes
that differ from current bytes are reported for contextual final-catalog review,
including deliberate corruption fixtures; none is silently waived.

Outputs are new allowlist.json, inventory.json, and summary.json under a fresh
twentyeighth_candidate_inventory result directory. Existing source/artifact,
ledger, Git, index, catalog, and checkpoint bytes are unchanged. No native,
proof-checker, build, process-inventory, or publication action is permitted.

Run once after source/spec freeze using locked offline uv and Python -B.
The inventory is not a final catalog or stage authorization. Root owns later
packaging, restoration, exact closure, independent publication audit, and Git.
