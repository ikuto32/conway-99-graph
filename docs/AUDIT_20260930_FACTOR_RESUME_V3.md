# V3 public JSON resume-boundary review

The v2 source constructed its nonmatching catalog as tuples. Serialization
saved lists, and literal comparison at the public `run --resume` boundary
therefore rejected both valid saved pilot checkpoints. The two failed cooling
stages created only manifests and failure records, before native input
creation. No new native proposals ran. The original engine's finite native
split controls and the independent saved pilot scores remain established in
their original scopes; they did not establish Python public resume usability.
The audit preserves a separate applicability addendum and all original bytes.

V3 changes the catalog element to `list(pair)`. An AST comparison checks that
reversing precisely this expression makes `problem()` identical to v2, and
all other algorithm helpers are unchanged. Only `run_chunks`, `main` and the
new public regression helper have orchestration changes. Review of the diff
confirms that research still requires the exact new wrapper/spec and old
native/builder/executable hashes in an independent gate. Its resume equality,
objective, engine and chain-count checks are retained. The calibration branch
is restricted to two named cores, fixed seed, two chains, one chunk,23/41/64
steps, temperature3.25 and30seconds; only the41-step case can resume. This
explicit finite calibration route does not fabricate research authorization.

The reviewer executes the actual new Python CLI into a fresh directory.
Each core runs23 steps, reloads the disk checkpoint in a new41-step process,
and compares every persisted chain field and the concatenated trace against
a separate64-step process. A different implementation independently reconstructs
every one of512 fresh proposal scores, RNG choices, saved acceptance decisions,
current/best updates and final states. Its full columnwise integer scores are
also compared with the independent raw-factor validator on24 final/best
objects. No producer scorer is imported by the reviewer. The underlying
producer CLI is intentionally invoked for black-box calibration, not trusted
as the expected-value implementation.

Five actual corrupted resume files change the target, catalog, objective or
engine identities; they must fail before native input creation. Additional
public CLI probes reject65 calibration steps, a missing41-step resume file,
and ungated research mode. The prior independently checked SRG243 positive
and malformed native/graph controls remain explicitly inherited through the
unchanged engine gate; they are not described as newly executed here.

The new gate binds all sources and every saved/replayed artifact. It supports
the corrected bounded orchestration and unchanged native engine. It does not
certify future heuristic scores, a cooling campaign, complete feasibility,
speedup or target resolution. Subsequent research outputs need their own
independent raw-state review.
