# CUDA再最適化の継続

目標は `srg(99,14,1,2)` の完全な構成、または一般の非存在証明であり、
未達成のまま継続している。ここで改善するphase-I値は、固定した部分配置に
対する必要な線形条件の違反量である。完成までの距離や達成率ではない。
数値ゼロ到達後の現在の起点は [完成条件と強化LP](GOAL_20260916_STAR_MARGINAL.md) に記録した。
以下の区間の小数表記は、証拠ファイルに保存した厳密な有理数の近似表示である。

## GPUメモリ配置の改善

`overlap_cp_gpu_layout_v2.cu` は、反復式、浮動小数点の精度、刻み幅、同期、
入力検査を保ち、幾何情報の置き場所と配列順序を変更した。
同じ512候補・500反復について旧版と新版を交互に3回ずつ実行した結果、
カーネル時間の中央値は **0.294509秒から0.107280秒** に短縮した（約2.745倍）。
比較した4,096個のスカラー値は6回の実行すべてで完全一致した。
プロセス全体の実測速度比は約1.731倍であり、カーネルの比とは区別する。

保存済みCPU計算などとの720,720値の照合、257候補を使うバッチ境界の検査にも
通過した。旧版のソース、実行ファイル、計算結果は保存したままである。
詳しい変更と検証範囲は
[CP_GPU_LAYOUT_V2_REVIEW.md](../acceleration/CP_GPU_LAYOUT_V2_REVIEW.md) にある。

## 再実行可能な探索手順

`search_cp_matching_v2.py` は、完全列挙の証拠と実際の初期配置・候補集合、
GPU検査と実際のソース・実行ファイルを明示的に照合する。
双対値はclip前に長さ・有限性・意味キーの重複を検査する。
複数回指定できる `--previous-summary` により、前の探索で評価済みの配置を
正確な辺集合でLP選択から除外する。GPUの粗い評価・再評価段階では除外しない。
正例3件・不正入力19件の検査に通過し、この検査はGPUやLPを実行せず、
探索用出力ディレクトリも作らない。

各探索は全候補500反復、選択した2,048候補2,000反復、64候補のLPという
同じ手順を使う。第2段階は共通の初期X/Yから再開し、初期の主目的値も
候補の最良評価に含める。近似双対値で候補を排除しない。
選択順序・入力対応・LPの有理数上下界・局所整合性は別の実装で検査する。

## 数値上ほぼ0の候補を整数条件で調べる

round9の候補226と2700の評価値は、それぞれ約 `4.05e-13` と `7.67e-13`。
保存した浮動小数点数を有理数として検査しても上界は小さな正数であり、
正確なLP実行可能性や整数解を証明したものではない。
候補226は24,574個から19,077個、2700は24,745個から19,388個の局所選択肢が残り、
全84頂点と768回・766回の削除を独立に再検証した。

`fixed_overlap_cnf.py` は、既存の一般CNFに固定配置を表す1,806単位節だけを追加する。
外側頂点の旧順序と現順序は60箇所で異なるため、頂点のラベルで変換する。
`audit_fixed_overlap_cnf.py` が両順序の全3,486変数、1,680自由辺、追加節、元CNFの
バイト同一性を独立に調べる。対称性を制限する追加節は使わない。

`run_fixed_overlap_sat.py` は時間・衝突回数を制限してCaDiCaL195を実行し、
SATモデルが得られた場合は全99頂点・693辺・4,851頂点対と固定配置の一致を
独立に検査してから保存する。制限到達はUNKNOWN、証明のないUNSATは未検証として記録する。
候補226は1,517衝突、2700は558衝突でUNSATを返した。その後、別に生成した証明ログの
独立DRAT検証にも通過した。これは各固定配置の排除であり、一般の非存在証明ではない。
結果は `acceleration/results/20260916_cp_zero_completion` に保存している。

候補226を数値的な起点として同符号側をさらに調べる別の探索は
`acceleration/results/20260916_cp_zero_neighborhood_226` に保存する。
これは実行可能解の採用や厳密な目的値改善を主張するものではない。

## 検証と対象範囲

`audit_cp_matching_search_v2.py` は、全候補の入力順序、候補の選択規則、
以前の候補の除外、GPU実装との対応を再検査する。選択した64候補の保存された
最終・平均反復は99頂点のモデルで再評価し、3種類のサイクル形状では
2,000反復を独立したCPU計算でも再生する。全候補のLP最適性を調べたわけではない。

`adopt_cp_search_best.py` は、厳密に改善する候補を上界順に検査し、完全局所選択肢と
頂点対整合性を独立検証できた最初の候補を採用する。ネイティブ検査の失敗や
時間制限を、そのまま独立した排除証明として扱わない。
正のLP下界を持たない候補が得られた場合は、完成問題の調査対象として記録する。

`build_cp_continuation_checkpoint.py` は、各資料のハッシュに加え、資料同士の
参照関係、前回と今回の初期配置の辺集合、採用候補の同一性も検査する。
索引の作成は証拠の取りまとめであり、新しい探索や一般の非存在証明ではない。
